# maps-to-tesla 導入手順

Google Maps で作った複数経由地ルートを Tesla のナビに送るための、
初回セットアップ手順です。上から順に進めれば、初めてでも
そのまま再現できるように書いてあります。

所要時間の目安: 30〜40 分（大半はアカウント側のフォーム入力です）

## 全体の流れ

1. GitHub Pages の置き場所を作る（公開鍵と認可ページ用）
2. Tesla Fleet API の利用登録をする（Client ID / Secret の取得と課金設定）
3. コンテナを起動する
4. セットアップ画面（ウィザード）で 5 つのステップを進める
5. 車に仮想キーを登録する
6. 動作確認
7. （任意）iPhone ショートカットを用意する

秘密情報（Client Secret、トークン、鍵）は、すべて自分のマシンの
`data` フォルダにだけ保存されます。GitHub に上げるのは「公開鍵」
だけで、これは仕組み上、公開するものです。

## 外部サーバーとの通信について

この道具が外部と通信するのは、次の相手と目的だけです。

- Tesla のサーバー（auth.tesla.com と Fleet API）:
  ログインの維持、車両の起床と状態確認、経由地の送信、
  ドメイン登録のため
- Google のサーバー（www.google.com）: 共有リンクの展開、
  場所の検索、ルート形状の取得のため。Google アカウントや
  API キーは使わず、匿名で問い合わせます

これ以外の外部通信はありません。利用状況の送信、広告、
解析といった処理もありませんし、今後追加する予定も
ありません（コンテナの更新時に Docker が ghcr.io から
イメージを取得しますが、これは配布の仕組みで、道具本体の
通信ではありません）。

## 1. GitHub Pages の置き場所を作る

公開鍵と、Tesla ログイン後に戻ってくるページ（認可ページ）を
置く場所です。無料です。

1. GitHub にログインし、新しいリポジトリを作ります
    - リポジトリ名: **`<自分のユーザー名>.github.io`**
     （例: ユーザー名が `taro` なら `taro.github.io`）
    - Public を選んで作成します
2. そのリポジトリに、次の 2 ファイルを追加します
   （GitHub の画面で「Add file → Create new file」でも構いません）
    - `.nojekyll` — 中身は空で OK です（このファイルが無いと、
     `.well-known` フォルダのファイルが公開されません）
    - `oauth-callback.html` — このリポジトリの `docs/oauth-callback.html`
     をコピーしたもの。**書き換えは不要**で、そのまま置いてください
     （コンテナのアドレスはファイルには入っていません。Tesla
     ログイン後に戻ってくるこのページで、初回だけブラウザに
     入力します。入力したアドレスはブラウザの中にだけ保存され、
     GitHub には載りません）

3. 数分待つと `https://<自分のユーザー名>.github.io/oauth-callback.html`
   が開けるようになります（開いて「認可コード」と表示されれば OK）

このあと使う「ドメイン」は `<自分のユーザー名>.github.io` です。

## 2. Tesla Fleet API の利用登録をする

1. https://developer.tesla.com に Tesla アカウントでログインします
2. 新しい登録を作成します（ポータルのボタンでは「Create App」
   のように表示されます。何かを作るというより、利用の
   届け出だと思ってください）
    - 名前: 短い名前を付けてください
     （記号の多い名前はフォームに弾かれることがあります）
    - **Allowed Origin（許可するオリジン）**:
     `https://<自分のユーザー名>.github.io`
    - **Redirect URI（戻り先 URL）**:
     `https://<自分のユーザー名>.github.io/oauth-callback.html`
    - スコープ（アクセス範囲）: 次の 3 つを有効にします。
     スコープは必要最小限にしてあり、この道具が要求するのは
     この 3 つだけです（充電の管理や車両設定の変更などの
     権限は要求しません）
        - `vehicle_device_data`（車両データ）
        - `vehicle_location`（位置情報）
        - `vehicle_cmds`（車両コマンド）
3. 作成後、**Client ID** と **Client Secret** が表示されます。
   手順 4 で使うので控えてください（Secret は再表示できない場合が
   あるので、その場で安全な場所にメモしてください）
4. 課金設定をします（Fleet API は従量課金のため必須です）
    - developer.tesla.com の Billing で支払い方法を登録します
    - 月の上限額（spending limit）を設定します。通常の個人利用なら
     月 $10 の無料クレジットの範囲で収まることがほとんどです。
     上限を超えると API が止まるだけで、勝手に高額請求される
     ことはありません
    - なお、本アプリ自体にも起床（wake\_up）の回数を抑える
     仕組みが入っています。wake\_up は 1 回 $0.02 と単価が高く、
     Tesla 側の制限も厳しい（1 分に 3 回まで）ため、本アプリは
     自分からの起床を 1 分に最大 2 回までに制限し、制限に
     近づいたら失敗させずに自動で待ちます。通常の使い方で
     月の上限に当たることは想定していませんが、これは目安で
     あり、料金が上限以下に収まることを保証するものでは
     ありません

> スコープは「開発者ポータルの設定」「手順 4-3 のドメイン登録」
> 「ログイン時の同意画面」の 3 か所で一致していないと、車両操作が
> 権限エラーになります。ここで 3 つとも有効にしておくのが大切です。

3 つのスコープがそれぞれ必要な理由は次の通りです。

- `vehicle_device_data`: 車両の状態確認と起床（wake\_up）に
  必須です。これが無いと車を起こせず、送信が始められません
- `vehicle_location`: ナビの経由地送信は、Tesla の権限区分で
  位置情報に属するため必要です
- `vehicle_cmds`: 経由地を車に設定する署名付きコマンドの
  実行に必要です

このほかに、ログイン自体のための標準的な権限（openid /
offline\_access）をサインイン時に使います。

## 3. コンテナを起動する

Docker が動くマシン（NAS / Raspberry Pi / PC など）で作業します。

```sh
git clone https://github.com/turu18-max/maps-to-tesla.git
cd maps-to-tesla
mkdir -p data
printf 'GHCR_USER=\nGHCR_TOKEN=\n' > .env
docker compose up -d --build
```

- 初回は手元のマシンでイメージを組み立てる `--build` で起動
  します（数分かかります）。組み立て済みイメージが公開されて
  いる環境では、`--build` を外した `docker compose up -d`
  でも起動できます
- `.env` は空で構いません（自動更新チェック用のログイン情報
  で、公開イメージを使う場合は不要です）
- 起動できたか確認します:

```sh
  curl http://localhost:8765/health
```

  `{"status":"ok"}` と返れば OK です

> コンテナの画面は自宅 LAN（や Tailscale）の中だけで開いてください。
> ポート 8765 をインターネットに直接公開しないでください。

## コンテナへの届き方（自宅と外出先）

ブラウザや iPhone ショートカットがコンテナの
アドレス（`http://<アドレス>:8765`）に **届く** ことで動きます。
届き方は、使う場所で変わります。

- **自宅（同じ Wi-Fi / LAN）**: コンテナの LAN アドレスで
  そのまま届きます。追加の仕組みは要りません
- **外出先**: 自宅のコンテナへ外から届く「閉じた経路」が
  別途要ります。手軽なのは **Tailscale** のような VPN で、
  コンテナのマシンと iPhone の両方にアプリを入れ、同じ
  アカウントでログインすると、外からでも自宅 LAN のように
  届きます（アドレスは `http://100.x.x.x:8765` の形になります）。
  Tailscale は個人利用なら無料枠で足ります

なお、セットアップ画面での Tesla ログインは、ログイン後に
ブラウザがコンテナへ戻ってくる流れなので、\*\*ブラウザが
コンテナに届く環境（自宅 LAN など）で行ってください\*\*。
Tesla のサーバーから自宅へ入ってくる接続は不要です
（通信はすべてこちらから出ていくだけです）。

外出先から送らない（自宅でだけ使う）なら、Tailscale は
入れなくて構いません。

## 4. セットアップ画面で進める

ブラウザで `http://<コンテナのLANアドレス>:8765/setup` を開きます。
上から順に 5 ステップです。

### 4-1. Tesla の登録情報

- Client ID / Client Secret: 手順 2 で控えた値を入力
- ドメイン: `<自分のユーザー名>.github.io`
- リージョン: 日本は **na** を選びます
- 「保存する」を押します。保存すると **API トークン** が自動生成
  されて画面に表示されます。これは iPhone ショートカット用
  （手順 6）の値なので控えてください。このブラウザには自動で
  保存されます

### 4-2. 公開鍵

- 「公開鍵を表示する」を押すと鍵のテキストが出ます
- 手順 1 の GitHub Pages リポジトリに、次の場所・名前で
  ファイルを追加します:

```
  .well-known/appspecific/com.tesla.3p.public-key.pem
```

  中身は表示されたテキストをそのまま貼ります
  （`-----BEGIN PUBLIC KEY-----` から `-----END PUBLIC KEY-----`
  まで全部です）

- ブラウザで
  `https://<自分のユーザー名>.github.io/.well-known/appspecific/com.tesla.3p.public-key.pem`
  を開いて、鍵が表示されることを確認します

### 4-3. ドメイン登録

- 公開鍵が上の URL で開けることを確認してから
  「ドメインを登録する」を押します
- 結果にドメインが返ってくれば成功です

### 4-4. Tesla ログイン

- 「Teslaでログインする」を押すと Tesla のログイン画面に移ります
- ログインして許可すると、手順 1 で置いた認可ページに戻ります
- 初回だけ、認可ページの「コンテナのアドレス」欄に、手順 3 で
  コンテナを動かすマシンのアドレスを入力します
  （例: `http://192.168.1.10:8765`）。入力したアドレスは
  ブラウザに保存されるので、次回からは入力不要です
- 認可ページの **「コンテナに送って認可を完了する」ボタン** を
  押します（コードを手でコピーしないでください。長いコードは
  貼り付けで壊れることがあります）
- 「認可が完了しました」と出れば OK です。セットアップ画面に
  戻ると、ステップ 4 が「✓ 済み」になります

### 4-5. 車の選択

- 「車両を取得する」を押すと、自分の車が一覧に出ます
- 車を選ぶと送信先に設定されます（VIN を手入力する必要は
  ありません）

## 5. 車に仮想キーを登録する

署名付きコマンドを車が受け付けるために、1 回だけ必要です。

1. スマホで Tesla アカウントにログインした状態で、
   ブラウザで次の URL を開きます:

```
   https://www.tesla.com/_ak/<自分のユーザー名>.github.io
```

2. Tesla アプリが開いて「キーを車に追加しますか」という
   確認が出るので、許可します
   （車の近くにいる必要はありません）

## 6. 動作確認

1. ブラウザで `http://<コンテナのLANアドレス>:8765/` を開きます
2. Google Maps で経由地のあるルートを作り、共有リンクを
   コピーして貼ります
3. 「経由地のまま送る」を押し、表示された経由地の一覧が
   正しければ「この内容で送信する」を押します
4. 車のナビに経由地ごとルートが設定されれば完了です

日常の使い方は [USAGE.md](USAGE.md) を見てください。
iPhone から共有シートで直接送りたい場合は、次の任意ステップに
進んでください。

## 7. （任意）iPhone ショートカットを用意する

Google Maps の共有から、1 タップでルートを車に送るための
ショートカットです。Web ページから送るだけなら、このステップは
不要です。

### 方法 A: 作成済みのショートカットを追加する（簡単）

作成済みのショートカットを配布しています。iPhone で次の
リンクを開いて追加してください。

- 共有リンク: https://www.icloud.com/shortcuts/677d1306d8d8433aaf842fb2710872b9

追加しただけでは動きません。使う前に、追加したショートカットを
開いて、次の値を自分のものに書き換えてください。

- **アドレス**（「URL の内容を取得」の URL、全部で 3 か所）:
  `http://192.168.1.10:8765` となっている部分を、自分の
  コンテナのアドレスに
- **API トークン**（送信アクションのヘッダー `X-Api-Token`、
  2 か所）: セットアップ画面ステップ 1 で表示された値に

### 方法 B: 自分で組み立てる

共有版を使わず、アクションを自分で並べて作る方法です。

用意するもの:

- コンテナに届くアドレス（自宅 Wi-Fi なら LAN アドレス、
  外出先からも使うなら Tailscale のアドレス。例: `http://192.168.1.10:8765`）
- API トークン（セットアップ画面ステップ 1 で表示された値）

> 外出先から使う場合は Tailscale が便利です。iPhone とコンテナの
> マシンの両方に Tailscale を入れ、同じアカウントでログインして
> ください。以下の手順ではアドレスを `http://<アドレス>:8765` と
> 書きます。自分の値に置き換えてください。

### アクションの構成（上から順に）

ショートカットアプリで新規ショートカットを作り、名前を
「Teslaへ送る」にして、次のアクションを順に並べます。

1. **（任意）Tailscale を接続**
    - Tailscale アプリのアクション「Connect」を置きます
     （外出先から Tailscale 経由で送る場合のみ）
2. **URL の内容を取得**（ウォームアップ）
    - URL: `http://<アドレス>:8765/health`
    - 方法: GET（ヘッダーは不要です）
    - 車が寝ていると初回の応答に時間がかかるため、先にこの
     リクエストでコンテナと接続を温めておきます
3. **URL の内容を取得**（本送信）
    - URL: `http://<アドレス>:8765/api/send`
    - 方法: POST
    - ヘッダー:
        - `X-Api-Token` : `<APIトークン>`
        - `Content-Type` : `application/json`
    - リクエスト本文: JSON、`url` キーに「ショートカットの入力」
4. **辞書の値を取得**
    - 取得: 値、手順 3 の結果からキー `route`
5. **変数を設定**
    - 変数名 `route結果` に、手順 4 の値を設定
6. **If 文**（`route結果` に「値がない」場合）
    - **待機** 5 秒
    - 手順 3〜5 と同じアクションをもう一度並べます
     （URL の内容を取得 → 辞書の値を取得 → `route結果` に設定）
    - **If 文**（`route結果` に「値がない」場合）
        - **通知を表示**: 本文「送信できませんでした。もう一度お試しください」
        - **ショートカットを停止**
7. **通知を表示**（成功通知）
    - タイトル: `Teslaへ送信しました`
    - 本文: 変数 `route結果`（文字として打つのではなく、
     変数として挿入してください）

最後に、ショートカットの詳細設定で **「共有シートに表示」** を
オンにし、受け付ける種類を「URL」にします。

## トラブルシューティング

- **送信時に&#32;`login_required`&#32;/&#32;`The refresh_token is invalid`**
  ログイン情報の失効です。`/setup` のステップ 4 から再ログイン
  してください。Tesla はログインのたびにトークンを更新する
  仕様で、本アプリは新しいトークンを必ず保存します。通常は
  再ログインが日常的に必要になることはありません
- **認可で&#32;`invalid_auth_code`&#32;などのエラー**
  認可コードは短時間で失効し、使い回しもできません。もう一度
  ステップ 4 のログインからやり直し、認可ページでは必ず
  ボタンを押してコンテナに渡してください
- **車が起きずにタイムアウトする**
  車両の起床（wake\_up）は Tesla 側で 1 分に 3 回までの制限が
  あります。本アプリは自分からは 1 分に 2 回までに抑え、
  制限に当たったら自動で待つ作りになっています。連続で
  失敗したときは 1〜2 分待ってから再試行してください。
  制限を超えてもペナルティはありません（429 が返るだけです）
- **`wake_up`&#32;で Forbidden / スコープ不足と言われる**
  `vehicle_device_data` スコープが不足しています。開発者
  ポータルで有効になっているか確認し、`/setup` のステップ 3
  （ドメイン登録）とステップ 4（ログイン）をやり直して
  ください。現在のスコープは `/setup/scopes`（要トークン）で
  確認できます
- **画面で「トークン」を聞かれる**
  セットアップを保存したブラウザと別のブラウザでは、
  API トークンの入力が必要です。ステップ 4-1 で控えた値を
  入れてください。控えを無くした場合は、コンテナの
  `data/config.json` の中の `api_token` の値がそれです
- **ステップ 5 で車両が取得できない**
  ログイン直後などに一覧が空のことがあります。少し待って
  もう一度押してください。それでも駄目な場合は、
  `data/config.json` に `"vin": "<自分の車のVIN>"` を直接
  書いても構いません（ファイルは都度読み込まれるので、
  コンテナの再起動は不要です）
- **住所をそのまま入力した地点が送れない**
  仕様です。経由地は Google Maps で場所（店舗・施設など）と
  して選んだ地点が確実です。座標だけの地点は、近くの登録済み
  の場所が 100 m 以内に無い場合、安全のため送信から外して
  結果に明記します
